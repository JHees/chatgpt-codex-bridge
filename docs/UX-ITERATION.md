# 设置、归档与结束操作候选

本记录对应经候选热加载后确认发布的 0.1.3 体验改动，保留下列实际验证范围与未覆盖场景。候选测试时保持旧正式版本号；正式自动更新包使用新版本号。0.1.2 的历史记录见 `UX-CANDIDATE.md`。

## 行为变化

- 设置的读取窗口和结束策略改用统一紧凑菜单，整块可点击、键盘选择、自动保存。结束策略为删除、归档、保留；默认删除不变。
- 归档使用原生 Chat `setArchived(id, true)`，回读 `is_archived` 确认。仅操作当前实例创建并可核对的会话，不扫描历史，不降级成删除。
- 主动终止与成功完成分开。UI 结束操作或执行端响应明确用户请求的 `finish(reason: "user-request")` 不要求先完成任务验收；自动删除/归档仍要求验收报告及规划端确认。只说“结束”时执行端默认保留。
- 结束会中断本地读取，并等待发送/检查阶段安全退出；不会再发送业务请求、格式修复或交付迟到动作。重复同策略结束合并处理，不再因读取窗口占用而返回 `CALL_BUSY`。
- Chat 仍在生成、用户介入或归属不明时不删除/归档；显示具体原因，可保留或在完成后重试。已经发出的原生清理请求未确定前，不能承诺保留能够撤销它。

## 可折叠说明

候选使用 Loader 通用 `collapsed-v1` 能力。摘要与显示更多/移除通过编辑器 NodeView 呈现，原始文档、原生序列化及提交关联保持不变。只有本插件登记的完整说明会折叠，用户同名标签不被全局扫描隐藏。默认收起；误落入隐藏正文的光标返回前面的用户正文，只有主动展开才编辑说明。编辑、移除和卸载保持原有归属检查。

旧 Loader 不提供该能力时继续短说明，不传未知参数。现有冲突段落渲染器不被覆盖；不支持折叠时显示原文。这不是独立附加上下文发送接口，文本仍交给模型。

发送后，由 Bridge 自身折叠用户消息内独立、完整的 Bridge Loader context 段落，保留用户正文。已有历史消息和新消息均默认显示「Chat 协作说明 · 显示更多」，可展开与收起。该展示识别不代表授权或会话归属校验；不改变消息数据，不搬移原生段落或替换其内容。草稿、助手示例、其他插件及混有用户正文或不完整的段落不折叠。停用或重载时移除控件并恢复原文显示。

切回旧草稿时，Bridge 摘要沿用「Chat 协作 · 模型 · 思考程度」，不额外标注“插件说明（已有草稿）”。模型信息取自该草稿原有说明，而不是当前任务的新默认值；只更新摘要展示，不改正文或绑定。模型提取限定在模型信息句，避免把前文“Chat 规划 / Chat plans”误当模型名。中英文完整说明回归通过，Bridge 完整检查共 161 项测试通过，已安装并热重载候选。

## 验证范围

- Bridge 接入 Loader 通用 `managed-v1` / `onChange` 通知：用户通过 Loader 的移除按钮清除说明后，当前任务协作立即关闭，不回调一次重复清除，也不自动重插。插件自己的协作开关关闭时通过 `clearContext()` 清除说明，包括单个完整且未改动的恢复草稿说明；其他插件、正文及历史消息不受影响。展开、收起、编辑通知不自动关闭协作。旧 Loader 不具备该通知能力时无法提供移除按钮的反向联动。
- 本轮完整检查：Bridge 类型检查、lint、163 项测试、构建及独立包校验通过；Loader 静态检查与 146 项 Node 测试通过，包含原生 Windows 源码提取路径、旧草稿显式清理、通知归属及无重复回调。仅更新 Loader 外部资源，未改原生二进制。两边候选均已热加载。
- 真实输入框验证「移除说明 → 关闭协作」及「关闭协作 → 移除说明」通过，原草稿不变，恢复关闭后无残留折叠框。未发送消息；旧草稿切换交互仍可由用户继续验收。

- 回归覆盖等待中结束、迟到结果、重复清理、任务面板操作、归档确认/拒绝/缺失能力/用户介入、设置自动保存与旧 Loader 兼容。
