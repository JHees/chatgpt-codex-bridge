# 0.1.2 体验候选与验收边界

本次按用户要求整理为 0.1.2，通过版本标签 CI 提供自动更新包；用户自行更新后进行实机验收。源码提交或 CI 打包通过不等于运行副本已更新。

## 本次实现

- Loader 作用域存储保存 host/task 偏好；内存只保留活动协作和草稿。已有任务不被新的全局默认开启覆盖。
- 短可见说明引用随包 skill，插件生成自然语言 Chat 简报、解析回复并核对原生消息归属。状态首行与正文分开；旧 JSON 回复仍兼容。
- 执行端完成报告加 Chat 确认后自动收尾；保留最后一份完成回执用于输出丢失恢复。清理失败留在活动状态，提供脱敏原因和手动重试。
- 专用 Chat 原标题添加 `[bridge] `，核对读回结果；手动改名或消息介入阻止自动删除。

## 入口检查和明确缺口

只读检查了当前 Loader 管理的精确主 renderer。App 自有客户端提供 `rename(id, title)` 和 `delete(id)`，不需要页面切换。目录和方法来自当前资源图，不写死文件哈希。

App 内部可传 `additionalContext`，但当前 Loader 的 composer 接口只有可见文本准备与原生提交回执；没有已验证的提交前中间件、独立上下文注册或执行任务结果回传接口。没有覆盖 App 全局发送函数，没有隐藏注入、第二次提交或仅用 CSS 隐藏原文。因此本次**没有实现完全免上下文的插件自主调度**，采用短说明回退，Loader 源码不变。

协作说明已接受的草稿可以准确迁移偏好；无说明的关闭草稿尚无同等可信的关联事件，关闭状态安全保持，但其临时模型覆盖不保证迁移。后续通用 Loader 接口需先证明草稿、原生提交与正式任务的关联，而不能从输入框清空或当前页面猜测。

## 验收边界

回归覆盖偏好跨实例恢复、默认值隔离、保存失败、简短可见说明、自然语言及旧 JSON 回复、重复/矛盾状态拒绝、自动清理、清理失败重试、丢失最终输出恢复、标题幂等、改名干预和删除拒绝。

完整 `npm run check` 已通过：类型检查、lint、14 个测试文件共 143 项测试、renderer 构建及单包 ZIP 校验。包括模拟 Chat 的两轮自然语言计划→实际计算核对→反馈→自动删除→最终回执续查，不能替代真实模型验收。首次沙箱运行被依赖网络策略阻断，随后以相同本地 npm 完成检查。Loader 工作树未修改，未重做原生构建。

本次未热更新运行包，未发起新 Chat 生成，未消费 Pro 测试额度。新的人类语言闭环、标题显示与自动删除仍需候选安装后的实机验收。此前 0.1.1 的模型闭环仅作为历史基线，不作为这些新行为的验收结果。
